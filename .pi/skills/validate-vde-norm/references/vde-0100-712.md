# DIN VDE 0100-712 — Special installations: Photovoltaic systems

German adoption of IEC 60364-7-712. The **most PV-specific** standard: rules
for DC circuits, string construction, module frame earthing, and separation of
DC from AC. This is the primary reference for string sizing in SolarPlanner.

## 1. DC system voltage classes (§712.4)

| Class | Max `V_oc` (string, coldest conditions) | Access / use |
|---|---|---|
| A | ≤ 60 V DC | general access, e.g. balcony PV |
| **B** | 60 V < `V_oc` ≤ **1500 V DC** | standard residential/commercial PV — the target class |
| C | > 1500 V DC | restricted to trained persons, commercial only |

**Hard rule for Class B:** the string open-circuit voltage at the **coldest
expected ambient temperature** must not exceed 1500 V.

### String voltage at cold conditions (the governing formula)

```
Voc_string(T_cold) = n_modules · Voc_STC · (1 + γ_Voc · (T_cell,cold − 25))
```

- `γ_Voc` = module `vocTempCoeff` in **%/K** (negative, e.g. −0.24 %/K) →
  divide by 100 for the factor: `γ = vocTempCoeff / 100`.
- `T_cell,cold` ≈ `T_ambient,min − 10 K` (cell can be ~10 °C below ambient at
  night with irradiation; a common planning assumption — state it explicitly).
- Because `γ_Voc < 0` and `T_cell,cold − 25 < 0`, the product is **positive** →
  `Voc` rises in the cold. This is why the cold check, not STC, governs the
  upper limit.

**Example:** 30 modules × 52 V Voc, γ = −0.24 %/K, T_cold cell = 15 °C:
`Voc_string = 30 · 52 · (1 + (−0.0024)·(15−25)) = 30 · 52 · (1 + 0.024) ≈
1638 V` → **exceeds 1500 V, non-compliant** — drop to 29 modules.

## 2. String current limits (§712.4 / with VDE-AR-N 4105)

- **One string per fuse:** each string is protected by its own DC fuse rated
  above that string's `I_sc` (see VDE 0100-443).
- **Paralleled strings on one MPPT:** the inverter's max input current per MPPT
  must cover the sum: `n_strings · I_sc(string) ≤ I_sc,max(MPPT)` — but the
  **fuse** is still sized to ONE string's `I_sc`.
- The inverter datasheet value `maxShortCircuitCurrentPerMpp` is the governing
  limit for how many strings may be paralleled per MPPT.

## 3. Module frame earthing (§712.4 / with VDE 0100-600)

- In **Class B** systems, module frames (and the inverter frame) must be
  connected to the **equipotential / PE** — unless the modules are Class I with
  an insulated frame and a specific exemption applies (rare; default: earth the
  frames).
- The DC circuit must be separated from AC circuits (separate conduits or
  spacing) per §712.4 — a planning note, not a numeric check.
- **Flat roofs:** the roof structure's equipotential must be considered; if the
  ballasted mounting is on an uninsulated roof, frame earthing via the structure
  may be possible — flag for the electrician.

## 4. String construction rules (planning-relevant)

- Modules in a string must be of the **same type** (or compatible within
  manufacturer's mixing rules) — SolarPlanner's `autoAssignStrings` already
  groups by module type, which is correct.
- **Mismatched strings on one MPPT:** paralleling strings with different `I_sc`
  or module counts causes circulating current — warn if a single MPPT gets
  strings of different length/type. (The app groups by type, so this is mostly
  avoided; still warn if the user manually builds mixed strings.)

## Properties SolarPlanner should persist for this standard

| Item | Property | Required? | Why (which check) |
|---|---|---|---|
| Module (inventory) | `voc` (V, STC) — *present* | **required** | cold/hot string voltage window. |
| Module (inventory) | `vocTempCoeff` (%/K) — *present* | **required** | temperature correction for the voltage window. Note: default −0.3 is a generic fallback; real values (−0.24…−0.35) should be entered per datasheet. |
| Module (inventory) | `isc` (A, STC) — *present* | **required** | fuse sizing + MPPT current limit. |
| Module (inventory) | `frameClass` ('I' / 'II') — *missing* | recommended | Class I (earthed frame) vs Class II (double insulated, no earthing needed). Drives the earthing warning. Add nullable text to `SolarModules`. |
| Inverter (inventory) | `maxInputVoltage` — *present* | **required** | upper bound of the voltage window (must be ≤ 1500 V for Class B). |
| Inverter (inventory) | `minInputVoltage` — *present* | **required** | lower bound: string must still start the inverter at hottest conditions. |
| Inverter (inventory) | `maxShortCircuitCurrentPerMpp` — *present* | **required** | parallel-string current limit per MPPT. |
| Inverter (inventory) | `dcVoltageClass` ('1000V' / '1500V') — *missing* | recommended | Some inverters are 1000 V DC only; the string cold check must use `min(1500, inverter_max)`. Add nullable text. |
| Project (site) | `tAmbientMinC` / `tAmbientMaxC` — *missing* | **required** for the voltage window | Coldest/hottest expected ambient. Can be pre-filled from weather data at the stored lat/lon, but must be user-confirmable. Add two reals to `Projects`. |
| Project (site) | `dcSystemClass` ('A'/'B'/'C') — *missing* (derivable) | recommended as a computed flag | Lets warnings key off the class; derive from max string `Voc(T_cold)`. |

## Formulas to validate in the app (the critical ones)

### The voltage window — currently INCOMPLETE in `autoAssignStrings()`
The app checks only:
```dart
if (inv.maxInputVoltage != null && newVoc > inv.maxInputVoltage!) break;
```
This uses **STC `voc`** and only the inverter max. It is missing:
1. **Cold-temperature correction** → `Voc(T_cold)` can exceed both the inverter
   max AND 1500 V even when STC passes. **This is the most important gap.**
2. **Hot-temperature lower bound** → at `T_cell,hot ≈ T_ambient,max + 30 K`
   (NOCT-equivalent planning assumption), `Voc(T_hot)` must still be ≥
   `minInputVoltage` (start-up voltage), else the inverter won't start on a
   hot day.

Corrected check (implement as a per-string validation, not just in auto-assign):
```
Voc_cold = n · Voc_STC · (1 + γ·(T_cell,cold − 25))
Voc_hot  = n · Voc_STC · (1 + γ·(T_cell,hot  − 25))
require: Voc_cold ≤ min(1500, inverter.maxInputVoltage)   // Class B + device
require: Voc_hot  ≥ inverter.minInputVoltage               // start-up
```

### Current check — present but incomplete
The app checks per-string `isc ≤ maxShortCircuitCurrentPerMpp`. It does **not**
check the **parallel sum per MPPT**: `n_strings_on_mpp · Isc ≤ I_sc,max(MPPT)`.
Add that as a post-assignment validation per MPPT.

## Warning triggers to implement (VDE 0100-712)

- ⚠️ `Voc_cold(string) > 1500 V` → "String-Spannung bei Kälte überschreitet
  die Systemspannungsklasse B (1500 V DC)" — suggest fewer modules per string.
- ⚠️ `Voc_cold(string) > inverter.maxInputVoltage` → exceeds device limit.
- ⚠️ `Voc_hot(string) < inverter.minInputVoltage` → "Wechselrichter startet
  an heißen Tagen nicht" — suggest more modules per string.
- ⚠️ `n_strings(MPPT) · Isc > inverter.maxShortCircuitCurrentPerMpp` → too many
  paralleled strings on this MPPT.
- ⚠️ Mixed string lengths/types on one MPPT → circulating current risk.
- ⚠️ Class I modules present but no frame earthing noted in the project →
  "Modulrahmen müssen mit dem Potenzialausgleich verbunden werden".
